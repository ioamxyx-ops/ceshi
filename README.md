# ceshi

一个待确定技术栈的项目仓库。当前仓库只包含通用基础结构，具体实现、构建方式和运行时将在项目方向明确后补充。

## 项目状态

- 项目类型：待确定
- 默认分支：`main`
- 当前阶段：初始化

## 目录约定

建议按职责逐步扩展，保持根目录简洁：

```text
.
├── .github/          # CI、Issue/PR 模板与维护配置
├── docs/              # 面向贡献者和用户的文档
├── src/               # 项目源代码（确定技术栈后启用）
├── tests/             # 自动化测试（确定测试方案后启用）
└── README.md
```

未使用的目录不需要提前创建；新增目录应在 README 或对应文档中说明用途。

## 开始贡献

1. 从 `main` 创建分支。
2. 先补充项目目标、运行环境和验证方式，再引入具体技术栈。
3. 保持提交聚焦，并在提交前运行适用于项目类型的检查。
4. 通过 Pull Request 合并到 `main`。

## 许可证建议

在明确版权归属和发布方式后再添加正式许可证文件：

- **MIT**：适合希望最大限度允许复用的通用项目，条款简洁。
- **Apache-2.0**：在宽松许可基础上提供更明确的专利授权条款。
- **GPL-3.0-or-later**：适合要求衍生作品继续以相同许可发布的项目。

在项目类型和版权持有人确认前，本仓库不预置许可证文本；选定后应将完整许可证保存为根目录的 `LICENSE`。

## 维护说明

CI 目前只验证仓库基础文件和 Markdown 文件存在且非空，不假设任何语言、包管理器或构建工具。项目类型确定后，应在 `.github/workflows/ci.yml` 中替换为真实的格式化、测试和构建步骤。
